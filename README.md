# AI-Powered Shopping Assistant

A production-oriented POC for a conversational e-commerce assistant.

## Stack
- React + TypeScript + Vite
- FastAPI + Python
- SQLite + SQLAlchemy
- Optional Ollama local LLM
- Pydantic validation
- Pytest
- Docker Compose

## Core architecture

```text
React
  |
  v
FastAPI
  |
  +-- Guardrails
  +-- LLM / deterministic fallback router
  |
  v
Allow-listed tools
  +-- search_products
  +-- get_order_status
  +-- get_delivery_estimate
  +-- create_order
  |
  v
SQLite
```

The LLM never receives database credentials, SQL, or internal schemas. All transactional facts come from backend tools.

## Run locally

### Backend

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python -m app.db.seed
uvicorn app.main:app --reload --port 8000
```

API docs: http://localhost:8000/docs

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173.

### Optional Ollama

The app runs without an LLM using a deterministic fallback router.

```bash
ollama pull llama3.2:3b
```

Set in `backend/.env`:

```text
LLM_PROVIDER=ollama
OLLAMA_MODEL=llama3.2:3b
OLLAMA_URL=http://localhost:11434
```

### Tests

```bash
cd backend
pytest
```

### Docker

```bash
docker compose up --build
```

## Purchase safety

Purchases require explicit confirmation. The backend validates current inventory before creating the simulated order.

## Accuracy and responsible AI

- Database is the source of truth.
- No arbitrary SQL generated by the model.
- Tools are allow-listed.
- Arguments are validated.
- Unknown information is not guessed.
- Purchase requires explicit confirmation.
- Tool calls are audit logged.
- Frontend cannot access DB credentials or schemas.

## Assumptions

1. Customer ID 1 is the authenticated demo customer.
2. Dataset is synthetic.
3. SQLite is used for reproducibility.
4. Purchase is simulated; no payment is processed.
5. Delivery dates are synthetic.
6. Ollama is optional.

## Production scale-out

Replace SQLite with PostgreSQL/MySQL, add OAuth2/OIDC, Redis, OpenSearch for large catalogs, OpenTelemetry, centralized logs, rate limiting, idempotency keys, payment/checkout integration, and horizontally scaled FastAPI instances.
